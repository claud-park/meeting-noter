# 🎙️ 회의록 자동화 봇

CLOVA Speech (STT) + Claude (요약/정제) 를 연결한 회의록 자동 생성 파이프라인

이 저장소는 두 가지 사용 방식을 다룹니다.

| 방식 | 설명 | 구현 위치 |
|---|---|---|
| **파일 기반 CLI** | 이미 있는 녹음 파일을 넘기면 회의록을 만들어 줍니다. | 이 저장소의 `meeting_bot.py` |
| **macOS 자동화 (Meeting Flow)** | `미팅 시작` / `미팅 끝` 한 마디로 녹음부터 회의록, 타임블록, 회의 전 브리핑까지 이어집니다. | [claud-park/meeting-flow](https://github.com/claud-park/meeting-flow) |

## 파이프라인 흐름

### 파일 기반 CLI

```
음성 파일 (.mp3/.wav)
    ↓
[CLOVA Speech] 화자 분리 + 타임스탬프 전사
    ↓
[Claude] STT 오류 교정 + 화자명 정규화
    ↓
[Claude] 요약 / 결정사항 / 액션아이템 추출
    ↓
회의록.md + 스크립트.txt 저장
```

### macOS 자동화 (Meeting Flow)

```
미팅 시작 ─→ Slack DND + 상태 "🎙 회의 중" + macOS 집중 모드 ─→ ffmpeg 녹음 시작
미팅 끝  ─→ 녹음 종료 ─→ 캘린더 이벤트명 바인딩 ─→ NCP 업로드
         ─→ CLOVA Speech 화자분리 ─→ Claude 요약 (회의 유형별 템플릿
         + 관련 프로젝트 링크 + 당일 브리핑 반영) ─→ Obsidian 저장 ─→ 완료 알림
         ─→ 내 액션 아이템 추출 ─→ "타임블록 후보 N건" 알림
              클릭 ─→ 검토 팝업 (시간 조정·승인) ─→ 캘린더 타임블록 / 미리알림 생성
                                                ─→ 회의록에 ## 📅 타임블록 기록

launchd 5분 틱 ─→ 반복 회의 15분 전 브리핑 노트 생성 (_briefs/) + 알림
               ─→ 미처리 후보 아침 재알림, 7일 지나면 만료
```

## 주요 기능 (macOS 자동화)

### 녹음과 환경 제어

- **두 가지 녹음 모드**: 대면 회의(오프라인)는 내장 마이크로 직접 녹음하고, 화상회의는 시스템 출력을 다중 출력 장치로 전환해 상대방 음성까지 함께 녹음합니다. 대면 모드가 집계 장치 대신 물리 마이크를 쓰는 이유는, 집계 장치가 간헐적으로 BlackHole 쪽 IO에 묶여 마이크 신호를 놓치는 문제를 피하기 위해서입니다.
- **무음 감지 프로브**: 녹음을 시작할 때 신호가 실제로 들어오는지 확인해서, 장치 인덱스 오류로 빈 파일이 만들어지는 상황을 일찍 알려 줍니다.
- **집중 모드 연동**: Slack DND만으로는 다른 앱의 알림음이 녹음에 섞이는 것을 막지 못하므로, 단축어 앱의 집중 모드를 함께 켜고 끕니다. 단축어 호출에는 5초 제한이 있어서 Shortcuts 서비스가 멈춰도 녹음이 막히지 않습니다.
- **Slack 상태 관리**: 회의 중에는 DND와 상태 메시지(`🎙 회의 중`)를 설정하고, 종료하면 복원합니다.
- **트리거 선택**: Raycast Script Command를 쓸 수 있고, Raycast가 없다면 `install-quick-actions.sh`로 macOS Quick Action을 설치해 단축키를 지정할 수 있습니다.

### 회의록 생성

- **캘린더 이벤트명 바인딩**: icalBuddy로 현재 진행 중인 일정을 찾아 회의 제목으로 사용합니다. `CALENDAR_NAME`에 캘린더를 쉼표로 나열하면 여러 계정에서 한꺼번에 회의를 찾습니다.
- **회의 유형별 요약 템플릿**: `TEMPLATE_RULES`에 `키워드:템플릿명`을 나열하면 회의 제목에 따라 `templates/<이름>.md`를 요약 형식으로 사용합니다. 템플릿을 추가할 때 코드를 수정할 필요가 없습니다.
- **관련 프로젝트 자동 연결**: Obsidian 프로젝트 노트 목록을 Claude에게 전달해 관련 프로젝트를 고르고, 회의록 끝의 `## 🔗 관련 프로젝트` 섹션과 frontmatter의 `projects`에 `[[노트명]]` 링크를 남깁니다. 실제로 존재하는 노트만 링크하므로 잘못된 링크가 생기지 않으며, `PROJECT_ALIASES`로 별칭도 지정할 수 있습니다.
- **사내 TLS 검사 환경 대응**: `truststore`를 주입해 TLS 검사 장비가 있는 네트워크에서도 API 호출이 동작합니다.

### 액션 아이템 → 타임블록

- **내 액션 아이템 추출**: 회의록의 `## ✅ 액션 아이템`에서 `MY_NAMES`에 적은 이름과 `공통` 항목만 골라 기한을 추정합니다. 날짜가 명시된 항목은 그 날짜를 쓰고, "다음 회의 전까지"는 캘린더에서 찾은 다음 차수 날짜를 쓰며, 단서가 없으면 기한 없음으로 분류합니다. 추출에 두 번 실패하면 경고 알림이 나갑니다.
- **타임블록 후보 알림**: 추출 결과는 `~/Meetings/.pending/`에 후보로 저장되고 "타임블록 후보 N건" 알림이 뜹니다.
- **검토 팝업**: 알림을 클릭하거나 `타임블록 검토` 트리거를 실행하면 로컬 팝업이 열립니다. 항목마다 체크, 종류(📅 타임블록 / ⏰ 미리알림), 제목, 날짜, 시간, 길이를 고칠 수 있고, 오른쪽에는 앞으로 7일 일정이 표시됩니다. 제안 시간끼리 겹치지 않으며, 먼 기한의 일정도 조회해서 반영합니다.
- **빈 시간 자동 제안**: `WORK_HOURS` 안에서 기한 전날부터 거꾸로 가장 늦은 빈 구간을 제안합니다. 오늘 마감이거나 오늘 알림인 항목이 과거 시각으로 제안되는 일은 없습니다.
- **반영과 기록**: **반영**을 누르면 승인한 항목만 macOS 캘린더(`TIMEBLOCK_CALENDAR`, 비우면 `CALENDAR_NAME`)와 미리알림(`REMINDER_LIST`)에 들어가고, 회의록 끝에 `## 📅 타임블록` 섹션이 기록됩니다. 같은 항목을 다시 반영해도 중복되지 않습니다.
- **검토 서버 보안**: 팝업 서버는 HTML 이스케이프, Host 헤더 검증, Content-Type 검증, 재반영 차단을 적용합니다.

### 회의 전 브리핑과 자동 정리 (launchd 틱)

launchd가 5분마다 `tick.py`를 실행합니다. (`./scripts/install-launchd.sh`로 설치합니다.)

- **회의 전 브리핑 생성**: 시작 `BRIEF_LEAD_MIN`분 이내인 회의 중에서, 같은 제목의 지난 회의록이 있는 반복 회의이거나 캘린더 제목에 `BRIEF_FORCE_TAG`(기본 `[brief]`)가 있으면 `_briefs/YYYY-MM-DD_<제목>.md`를 만들고 알림을 보냅니다. 알림을 클릭하면 Obsidian에서 열립니다.
- **브리핑 내용**: 지난 `BRIEF_HISTORY_COUNT`회 회의의 결정 사항과 미완료 액션 아이템(내 것 먼저)을 그대로 옮기고, 관련 프로젝트 근황과 확인할 질문은 Claude가 작성합니다.
- **브리핑을 회의록에 반영**: 같은 날 `미팅 끝`으로 회의록을 만들 때 이 브리핑이 요약 프롬프트에 함께 들어가서 지난 항목의 진행 상황이 반영되고, 회의록 frontmatter에 `brief: "[[...]]"`로 연결됩니다.
- **미처리 후보 재알림과 만료**: 처리하지 않은 후보는 다음 날 `MORNING_REMIND_AT`에 한 번 더 알림이 오고, `PENDING_EXPIRE_DAYS`가 지나면 `.pending/expired/`로 옮겨집니다.
- **안정성**: 브리핑 탐색이나 링크 기록이 실패해도 회의록 저장은 막히지 않습니다. 손상된 후보 파일은 격리되어 다른 후보의 처리를 방해하지 않습니다.

### 설치와 진단

- **`setup.sh`**: Homebrew 의존성, Python 가상환경, `config.env` 대화형 생성, launchd 틱 설치를 한 번에 처리합니다.
- **`doctor.sh`**: `config.env` 문법(따옴표 짝 불일치 등)과 각 연결, launchd 틱(`com.meetingflow.tick`) 로드 여부를 점검합니다.
- **`SETUP_GUIDE.md`**: AI 어시스턴트(Claude Code 등)가 설치를 도울 수 있도록 설치 절차와 실제 설치에서 검증된 트러블슈팅 표를 정리한 문서입니다.

자세한 설치와 설정 방법은 [meeting-flow README](https://github.com/claud-park/meeting-flow#readme)를 참고하세요.

## 파일 기반 CLI

### 설치

```bash
pip install -r requirements.txt
cp .env.example .env
# .env 파일을 열어 API 키 입력
```

### 필요한 API 키 발급

#### CLOVA Speech
1. [네이버 클라우드 플랫폼](https://www.ncloud.com) 로그인
2. AI Services > CLOVA Speech > 이용 신청
3. 도메인 생성 → **InvokeURL** + **Secret Key** 복사

#### Anthropic Claude
1. [console.anthropic.com](https://console.anthropic.com) > API Keys
2. 새 키 생성 → 복사

### 사용법

```bash
# 기본 사용
python meeting_bot.py \
  --file 회의녹음.mp3 \
  --title "AX팀 주간회의" \
  --attendees "이비집사,Alex,Jefferey"

# 참석자 없이 실행 (화자 A/B/C로 표시)
python meeting_bot.py --file meeting.wav --title "기획 회의"
```

### 출력 예시

```
output/
├── 20250601_143022_AX팀_주간회의.md          ← 최종 회의록
└── 20250601_143022_AX팀_주간회의_transcript.txt ← 정제 스크립트
```

### 회의록 형식

자동 생성되는 Markdown 회의록 구조:
- 📋 **회의 요약** - 3~5줄 핵심 요약
- ✅ **결정 사항** - 테이블 형식
- 🎯 **액션 아이템** - 담당자 + 마감일 포함
- 💬 **주요 논의 내용** - 주제별 정리

### 지원 파일 형식

mp3, m4a, wav, aac, ogg, flac (CLOVA Speech 지원 포맷)

## 주의사항

- 회의 파일 1개당 CLOVA Speech + Claude API 비용 발생
- 60분 회의 기준 약 8~10분 소요
- 개인정보 포함 회의는 사내 보안 정책 확인 후 사용
- macOS 자동화는 마이크, 캘린더, 미리알림, 자동화 권한이 필요하며 `config.env`에 API 키가 들어가므로 절대 커밋하지 않습니다.
